# v0.2.0-alpha scope decision

- Status: Owner approved / implementation authorized
- Decision date: 2026-08-27
- Supersedes: `v0.2.0-alpha-scope-decision-draft.md` as the active planning decision
- Preserves: all v0.1.x release facts and fixed-knowledge behavior

## Objective

v0.2.0-alpha completes the fixed-knowledge lifecycle and exposes a narrow,
stable, testable call boundary for the existing `FIXED_ONLY` governance kernel.

## Approved scope

1. Complete Supersede, Tombstone, and historical Replay semantics.
2. Freeze a narrow in-process Library API around `FIXED_ONLY` requests,
   results, evidence, lifecycle operations, and exact historical references.
3. Freeze an Adapter SPI that allows an external adapter to translate public
   contracts without referencing Observer or Engine internals.
4. Provide an in-process reference adapter and contract tests.
5. Add compatibility and upgrade gates from v0.1.x, including exact contract,
   schema, storage, and Golden behavior checks.
6. Preserve append-only audit, immutable released artifacts, explicit UNKNOWN,
   and fail-closed behavior.

## Explicit exclusions

- K2 controlled dynamic knowledge sources or acquisition;
- K3 `DYNAMIC_ONLY` or `HYBRID` runtime implementation;
- HTTP service, MCP, UI, Worker, LLM, vector database, or search runtime;
- Observer or Engine integration and project references;
- Consumer/Enterprise Skill behavior or product-specific report logic;
- real regulated knowledge, production authorization, or deployment;
- release, tag, push, or public availability without separate approval.

## Compatibility rule

The v0.2 implementation must not silently change v0.1.x fixed-resolution,
evidence, Domain Profile, or Golden semantics. An incompatibility must fail
closed, be documented, and receive an explicit versioned migration path.

## Exit gate

`KG_V0_2_INTERNAL_ENGINEERING_PASS` requires:

- all v0.1.x regression and Golden tests passing;
- lifecycle positive and negative tests for Supersede, Tombstone, and Replay;
- Library API and Adapter SPI contract tests;
- restart, concurrency, idempotency, and immutable-history tests;
- v0.1.x storage/contract compatibility evidence;
- zero Observer/Engine code or requirement changes;
- independent re-verification before any release decision.

Passing this internal engineering gate does not imply release or production
readiness. ADR-012 gates remain independent.
